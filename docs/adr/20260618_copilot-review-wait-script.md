# ADR: Copilotレビュー完了待機スクリプトの実装

- **Date**: 2026-06-18
- **Status**: Proposed
- **Issue**: #33

---

## Context

PR に Copilot レビューを依頼した後、完了を待つ手段が自然言語の指示のみだと毎回挙動にばらつきが出る（ポーリング間隔・終了条件・エラー処理）。スクリプトで挙動を固定したい。

Copilot は 1 回のレビューサイクルで複数回 `COMMENTED` を投稿するため、「レビュー完了」の判定が難しい。単純に「最新レビューが Copilot か」を確認するだけでは不十分。

配置先の検討（Discussion #32）:

| 案                                 | 評価                                        |
| ---------------------------------- | ------------------------------------------- |
| CLAUDE.md のワークフロー手順に記載 | Hotfix 等で手順を飛ばした場合は適用されない |
| Skill として実装                   | トークン消費が重い・オーバースペック        |
| CLAUDE.md に汎用ルールとして追記   | ワークフロー問わず常に適用される ← **採用** |

## Decision

### 完了検知：ベースラインカウント方式

スクリプト起動時点の Copilot レビュー件数 N を記録し、N+1 件以上になった時点で通知・終了する。  
レビュー依頼のたびにスクリプトを起動し直すことで複数サイクルに対応する。

```
起動時: Copilotレビュー件数 = N件（前回分）
↓ ポーリング（30秒間隔）
件数が N+1 件以上になったら通知して終了
```

### `scripts/wait_copilot_review.py` の実装

- `gh api` で PR のレビューリストを取得し、`user.login` が `"copilot-pull-request-reviewer[bot]"` であるレビューをカウント
- 起動時のカウントをベースラインとして保持
- 30 秒間隔でポーリング
- ベースライン + 1 以上になったら `✅ Copilot review completed!` を出力して終了
- 実行コマンド: `uv run python scripts/wait_copilot_review.py <PR番号>`

### CLAUDE.md への汎用ルール追記

`## ルール（厳守）` セクションに「Copilotレビューの待機」として追記する。  
ワークフロー手順ではなく汎用ルールとして置くことで、Hotfix 等あらゆる作業フローに適用される。

ルール内容:

- Copilot レビューを依頼したら、必ず `uv run python scripts/wait_copilot_review.py <PR番号>` を実行して完了を待機する
- スクリプトが完了通知を出すまでフィードバックの確認・対応を開始しない

## Consequences

### ポジティブ

- Copilot レビュー完了待機の挙動がスクリプトで固定され、指示のばらつきがなくなる
- ベースラインカウント方式により複数回のレビューサイクルにも対応できる
- CLAUDE.md の汎用ルールとして置くため、Hotfix 等あらゆるフローで適用される

### ネガティブ

- スクリプト実行を手動で起動する必要がある（CI への組み込みは対象外）
- `gh api` が認証済みであることが前提（未認証環境では動作しない）

## Implementation Notes

- Copilot bot のログイン名は `"copilot-pull-request-reviewer[bot]"` を使用する
- `gh api repos/{owner}/{repo}/pulls/{pr_number}/reviews` で取得したレビューリストをフィルタリング
- `uv` 依存パッケージは `requests` を使わず標準ライブラリ + `subprocess`（gh CLI 呼び出し）のみで実装し、`--with` 引数不要にする
- ポーリング中は経過時間と現在のカウントを表示し、待機状況が把握できるようにする
